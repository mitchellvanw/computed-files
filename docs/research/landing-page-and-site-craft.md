# Landing page, site craft, and the catalogue of regions nobody writes

Research date: 2026-09-08. Sources are primary: the landing page itself, the tool's own docs, the repository file, the spec, the issue thread. Every claim carries a `[n]` pointing at the Sources list. Paragraphs marked **Analysis** are my own reasoning, not sourced. Measurements taken against this repository at `65650a8` are labelled as such and are reproducible from a clone. This file builds on [`computed-markdown-prior-art.md`](computed-markdown-prior-art.md) and does not repeat its survey of cog, mdsh, markdown-magic and embedme as region rewriters; where a tool from that survey does something worth stealing on its *site*, it appears here instead.

## Summary

- **Nobody in the surveyed corpus keeps the artifact on their landing page equal to what their tool emits today.** Biome's homepage formatter panes are hand-pasted files last touched 2024-04-08, its linter diagnostic 2024-06-04, while the site advertises v2.5 [2][3]. uv's hero benchmark is a PNG dragged into a GitHub comment box, in a repo whose `BENCHMARKS.md` documents the exact `--json`-emitting command that produces the data [5][6]. mise labels its own homepage terminal block **"Illustrative output"** [9]. `just`'s README opens with a PNG of a justfile and a hand-written fake transcript [15]. `charmbracelet/vhs` — whose tagline is writing terminal GIFs as code — has no tape-rendering step in its own CI and serves a README GIF from a CDN path its checked-in tape does not write [24]. This is the single strongest asset the page has and it is not on the page.
- **The measured decay rate is available from this repo's own history and should be on the page.** Since the dogfood commit `3624abc`, the tree region's body changed in **8 of 41 commits** — about one commit in five moved a fact that a hand-written tree would have got wrong, silently. `computed check` across the whole repo runs in **under 10 ms** and executes nothing (measured, `65650a8`).
- **Apache Airflow has already built `computed` by hand, in Python, for one repo.** `AGENTS.md` carries `<!-- START generated-commands, please keep comment here to allow auto update -->` … `<!-- END ... -->`, regenerated by a pre-commit hook, with a *separate* validator that introspects the live Click tree and whose docstring cites two real drift bugs as its motivation [123][124][125]. That is `run` and `check`, without the sums, unportable. It is the best single piece of evidence in this file.
- **Every check mode in the category re-runs the generator.** terraform-docs `--output-check` renders the full document and `bytes.Equal`s it [75][76]; cog `--check` re-executes the embedded Python [72]; mdsh `--frozen`, embedme `--verify`, doctoc `--dryrun` the same [89][90][77]. Kubernetes' `hack/lib/verify-generated.sh` spins up a `git worktree`, runs the generator inside it and counts `git status --porcelain` lines [51]. **Storing a fingerprint of the inputs and checking cheaply is an unoccupied posture.** That is the two-sum closer, and it is the sharpest thing the site can claim.
- **The vendors give contradictory advice because the third option does not exist.** Cursor: *"Reference files instead of copying their contents—this keeps rules short and prevents them from becoming stale as code changes"* [99]. GitHub: requests to *"refer to external resources"* are listed among instructions that *"may not have the intended results"* [100]. Anthropic's `/doctor` proposes cutting *"directory layouts, dependency lists, and architecture overviews"* [91] while the feature overview tells you to put *"project structure"* in [94]. Everyone is choosing between a fact that rots and a fact the agent does not have.
- **Aider is the framing.** It computes the structural half of repo context from the AST every turn, PageRank-ranked over a reference graph, binary-searched to a 1k-token budget, mtime-cached [104][105][106] — and keeps a separate, two-line, hand-written `CONVENTIONS.md` for taste [108]. Every Markdown context-file format merges both halves and hopes. In Böckeler's taxonomy [116], `AGENTS.md` sits in the *inferential feedforward* cell; a computed region moves its derivable fifth into the *computational* cell, which her table has but has no documentation example for.
- **Meet the counter-evidence head on.** ETH Zurich's *Evaluating AGENTS.md* found *"repository overviews, although popular and recommended by model providers, are not helpful"* and cost 20%+ more tokens [121]. It measures a correct overview's benefit, not a wrong one's cost. Roughly **10–20% of a real context file is mechanically derivable** [D3 corpus, §5.4], and it clusters in the first fifth of the file. Pitch `computed` as fixing the fifth that rots, not the file.
- **The landing page never shows an `exec` region.** `docs/index.html` contains zero `computed exec` markers (measured); the only region a first-time reader ever sees is a file tree. The loader that does the interesting work — arbitrary command output with declared inputs — is invisible until the second page.
- **The site's own tables are the rot surface.** The exit-code table exists in four places (`README.md`, `docs/how-it-works.html`, `docs/spec/computed-v0.md`, `REFERENCE.md`), the command synopsis in four, the state table in three, the loader table in two. Exactly one of those twelve copies is a computed region (measured). CI runs `computed check` with no paths, which walks `.md` only — **the two HTML pages are not checked at all**.
- **`computed` writes HTML regions today with no code change.** Verified in a scratch repo: an `as=raw` exec region and an `as=raw` tree region both render into an `.html` file and `computed check` exits 0. What does *not* port is the `fence` sink, which emits literal backticks and unescaped body text into HTML. The markers port; the sinks do not.

## 1. What the site is now, and what a first-time reader never learns

**Measured against `65650a8`.** `docs/index.html` is a single-column page of 312 lines: hero with a rendered `CLAUDE.md` card and three numbered callouts, a "why" section citing Böckeler, a three-card "Three steps, two commands", a five-row comparison table against cog/mdsh/markdown-magic/embedme, a two-column "Get started" / "Wire it in", and a footer. `docs/how-it-works.html` is 420 lines under nine anchors: markers, hashes, loaders, states, edits, trust, commands, writes.

What a first-time reader finishes the landing page still not knowing:

| Not on the page | Where it lives instead |
|---|---|
| What an `exec` region looks like | `how-it-works.html`, second page (0 occurrences of `computed exec` in `index.html`) |
| That a region can be *anything a command prints* | nowhere on the landing page |
| What `computed run --dry-run` output looks like | nowhere on the site |
| What a refusal actually reads like on stderr | `README.md` only |
| That the tool is used on its own repo, verifiably | claimed in prose, never shown |
| How fast `check` is | nowhere |
| What to compute *first* in a repo you already have | `discover-regions` skill only |

**Analysis.** The page is well-built and argues the mechanism honestly, but it sells the *guarantee* (two sums, no rerun) before it sells the *capability* (any command's output, kept true). A reader who does not already feel the pain of a stale `CLAUDE.md` has no reason to care about a hash. The tree region is the least interesting thing the tool does and it is the only thing the fold shows. Section 6's catalogue is the missing content: the page needs a reason to want thirty regions, not one.

## 2. Landing-page craft: mechanics from pages that convert

Ten pages, fetched 2026-09-08. Only the mechanic is reported; "it looks nice" is omitted.

### 2.1 What is above the fold, and what the first code block does

| Page | Headline (verbatim) | First code block | Artifact visible without scrolling? |
|---|---|---|---|
| Bun [1] | "Bun is a fast JavaScript runtime & toolkit. All in one." | `curl -fsSL https://bun.sh/install \| bash`, tabbed macOS+Linux / Windows, with a **"View install script ↗"** link | Yes — an animated install benchmark immediately below |
| esbuild [8] | "An extremely fast bundler for the web" | none on the page at all | Yes — the chart *is* the fold |
| uv [4][5] | "An extremely fast Python package and project manager, written in Rust." | `curl -LsSf https://astral.sh/uv/install.sh \| sh`, **after** the chart and the highlights | Yes — a bar chart before any prose |
| Biome [2] | "One toolchain for your web project" / "Format, lint, and more in a fraction of a second." | package-manager tabs pairing install **with the command that makes the artifact** | No — the artifact is the second screenful |
| mise [9] | "Everything in its place." | `curl https://mise.run \| sh` with a Copy button | Yes, but captioned **"Illustrative output"** |
| Turborepo [11] | "Your codebase, faster" / "Turborepo is the build system for coding agents." | `npm i turbo` | Yes — mocked animated terminal panes |
| Tailwind [13] | "Rapidly build modern websites without ever leaving your HTML." | none — the hero is an HTML snippet beside its rendered result | Yes — input beside output |
| oxc [12] | "The JavaScript Oxidation Compiler" | none | Yes — per-subproduct benchmark charts |
| Prettier [14] | — | **none anywhere on the page** | No |
| Astral [7] | "Next-gen Python tooling" | none in the hero | No — the hero visual is a decorative pattern |

**The strongest single mechanic: Biome's two-line install tabs** [2]. Each tab shows `npm i -D -E @biomejs/biome` *and* `npm @biomejs/biome format` — install plus the command that produces the artifact the reader just looked at. The same widget is repeated three times down the page with `lint --write` and `check --write`, matched to the section above it.

**The second strongest: Bun's `reproduce →` link next to every number** [1]. Each benchmark carries its methodology inline — *"T3-stack app, 25 direct dependencies, ~220 packages in the lockfile · warm cache · lockfile present · node_modules removed · Linux x64, EPYC 9R14 · every package manager at defaults · medians of 3"* — and a link to the bench directory in the repo. The claim and the recipe travel together.

**Bun's honesty label is worth copying verbatim in spirit** [1]: the five-step clickable terminal says *"Every step below is a real command with real output — click one, or just watch"* and is footnoted *"Output abridged from Bun v1.4.2."* A claim of realness, a version stamp, and an admission of abridgement.

### 2.2 The second screenful

Three patterns, in descending order of how well they work:

1. **The artifact.** Biome shows two syntax-highlighted panes labelled literally `CODE` and `OUTPUT` — a 20-line ugly JSX component in, a 34-line formatted one out — then the full linter diagnostic rendered as HTML, character-level diff colouring and `·` middots for spaces included [2].
2. **The decomposition.** Bun: "Four tools, designed together. / Adopt one, or all of them", each card labelled by what it *replaces* [1]. oxc gives each sub-product its own multiplier against its own named incumbent, so a reader who cares about one thing still gets a number [12].
3. **The migration reassurance, placed early.** mise: *"Coming from asdf? Your `.tool-versions` already works"* [9]. Bun: `bun install` and `bun test` drop into existing Node projects [1].

### 2.3 Proof devices, and two worth stealing outright

**ripgrep's benchmark table** [16] is the best-engineered proof in the corpus, and it is Markdown in a repo:

- **The full command is a column** — `rg -n -w '[A-Z]+_SUSPEND'`, `LC_ALL=C git grep -E -n -w '...'` — so the reader can rerun it or spot the unfairness.
- **A "Line count" column that is not the point** — 536, 536, 536, 534, … 2677 — silently proving the tools did the same work and quietly showing that `ack` did not.
- **Explicit hardware and an explicit disclaimer**: *"Timings were collected on a system with an Intel i9-12900K 5.2 GHz. Please remember that a single benchmark is never enough!"*

**esbuild's chart is CSS divs, not an image** [8]. `<figure class="bench" style="…">` with four rows and the numbers as literal text: esbuild 0.39s, parcel 2 14.91s, rollup 4 + terser 34.10s, webpack 5 41.21s. The caption does the whole argumentative job — *"a production bundle of 10 copies of the three.js library from scratch using **default settings**, including minification and source maps"* — pre-empting the "you tuned it" objection in two words. **Analysis:** because the chart is text rather than an image, it is exactly the shape a computed region can write. A benchmark table rendered from a command, in a page under `computed check`, would be the first honest one on the internet.

**Astral's testimonial selection rule** [7]: all three quotes testify to *one* claim from three angles, and two describe a specific behaviour — *"Ruff is so fast that sometimes I add an intentional bug in the code just to confirm it's actually running."* Specificity beats enthusiasm.

**difftastic's landing page structure** [32] is the closest usable template: four cards, each one *misconception + image of the artifact + one sentence*, with headings whose first word is coloured ("**Understand** What Actually Changed", "**Real** Line Numbers"), then a single `<h2>60 Second Demo</h2>` with an embedded asciinema player below them. The cards convince; the recording proves. Naming the duration in the heading is a cheap trick that lowers the bar to pressing play.

### 2.4 The negative results, which are the most useful findings

**Prettier** — the most famous "your value is a diff" tool on earth — **has no diff, no code block, and no install command on its landing page** [14]. Its freshest social proof cites State of JS **2021**. It gets away with this because everyone already knows what it does. **Analysis:** that is the inverse of `computed`'s position. Every argument for showing the artifact is stronger for an unknown tool than for a famous one.

**Astral's own marketing site converts worse than uv's docs landing page** [7][4]: `astral.sh` leads with a decorative pattern and has no install command in the hero; `docs.astral.sh/uv` leads with a chart and gives you the curl line. The docs page is the better landing page.

**Turborepo now sits on `computed`'s exact ground** [11]: *"Turborepo is the build system for coding agents. Developers, CI, and agents never do the same work twice."* — with a "For humans" / "For agents" tab toggle in the hero, an "Agent Skills" section, and a `turbo docs "remote caching"` command so agents can search current docs from the terminal. Fetched without a browser User-Agent, `turborepo.dev` returns an **agent-oriented index** pointing at `/llms-full.txt` and stating any URL can be suffixed `.md`. **Analysis:** the agent-facing half of the web is converging on Markdown with owned regions, which is already `computed`'s output format. This is a positioning tailwind and also a warning that the ground is being claimed.

## 3. Showing the artifact when the artifact is a diff

`computed`'s output is a diff inside a Markdown file. Six ways tools present a file transformation, with what each costs and whether it rots.

| Family | Cost to make | Cost to keep | Text? | Regeneratable | Verified against the tool |
|---|---|---|---|---|---|
| Screenshot PNG — just [15], ripgrep [16], delta [33], difftastic [31], oxc [12] | minutes | none, until it lies | **no** | no | **no** |
| Recording — asciinema [22], svg-term [27], termsvg [28], agg [26] | ~15 min + deps | none, until it lies | at playback only | no | **no** |
| Scripted GIF — **vhs** [24] | tape + `ttyd` + `ffmpeg` | a CI job | **no** (GIF) | **yes** | ran, not checked |
| Live playground — Prettier [17][18], TS [19], Ruff [20], Biome [21] | weeks, WASM/worker build | ~none, runs live | **yes** | n/a, is live | **yes**, but off-page |
| Build-time check — **twoslash** [29][30] | notation + compiler | build time | **yes** | **yes** | **yes**, types only |
| **A `computed` region** | one marker line | pre-commit + `check` in CI | **yes** | **yes** | **yes**, any command |

**The gap, stated plainly.** The tools that produce *verified* artifacts (playgrounds, twoslash) need either a WASM build and a live app or a language-specific compiler. The tools that are cheap (screenshots, recordings, vhs) produce **images**, which cannot be diffed in review, cannot be read by a coding agent, and cannot live inside a `CLAUDE.md`. The cheap-and-text-and-verified corner is empty.

### 3.1 vhs, and the split verdict that makes the point

`charmbracelet/vhs` describes itself as *"Write terminal GIFs as code for integration testing and demoing your CLI tools"* — testing first [24]. The `.tape` format is a small imperative language; `examples/neofetch/neofetch.tape` emits four outputs from one tape and reads in part:

```
Output examples/neofetch/neofetch.gif
Output examples/neofetch/neofetch.mp4
Set TypingSpeed 75ms
Type "neofetch"
Sleep 500ms
Enter
```

The assertion primitive is `Require <string>` — *"Ensure a program is on the $PATH to proceed"* — so a tape fails rather than silently recording a `command not found` [24].

**vhs itself does not dogfood it.** Its workflows are `build.yml`, `dependabot-sync.yml`, `goreleaser.yml`, `lint-sync.yml`, `lint.yml`, `nightly.yml`; none renders a tape, and the README's hero GIF is served from `stuff.charm.sh`, not from the `examples/neofetch/neofetch.gif` its committed tape writes [24]. **`charmbracelet/vhs-action` does** [25]: `.github/workflows/gif.yml` runs on pushes touching `*.tape`, renders, and commits with `commit_message: 'chore: update generated VHS GIF'`. Its `gif-pr.yml` is worth copying wholesale — on a PR touching `vhs.tape` it renders, uploads, then **upserts** a PR comment by searching for a `<!-- bot: gif-commenter -->` marker and editing that comment rather than posting a new one.

**Analysis.** Three contrasts fall out, and all three favour `computed`. (a) A GIF cannot be diffed in review, grepped, or read by an agent; a region can. (b) vhs *regenerates* — `git-auto-commit-action` silently rewrites the GIF and moves on — where `computed check` *fails the build*, and ADR 0005 and ADR 0006 make drift and tampering separately named failures. (c) `Require` proves the demo *ran*; nothing proves it is *right*. A tape typing `foo --bar` renders happily after `--bar` is renamed.

### 3.2 Two mechanics from the Prettier playground worth taking

I read `prettier/prettier/website/playground/*` rather than the rendered SPA [18].

**"Copy markdown" / "Report issue".** `markdown.js` builds a pasteable block containing the version, a playground link, the CLI options, the input fenced, and the output fenced — each fence preceded by `<!-- prettier-ignore -->`, because the generated Markdown has to defend itself against the tool that produced it. `Report issue` opens `github.com/prettier/prettier/issues/new?body=` with `MAX_LENGTH = 8000 - ISSUES_URL.length`, falling back to the clipboard with the placeholder *"The issue body has been saved to the clipboard. Please paste it after this line! 👇"*.

**The idempotency check.** A debug toggle labelled `show second format`, backed by:

```js
if (formatted === reformatted) return "✓ Second format is unchanged.";
```

and in the report generator, a **"Second Output:"** section that appears *only when the tool disagrees with itself*.

**Analysis.** That is conceptually `computed check`: run twice, show the delta only if there is one, and state the passing case out loud. `computed run` twice being a no-op is already an acceptance criterion in the spec; the site currently states it as a bullet in "Try it". Rendering it as a checkmark line — *"✓ Second run wrote nothing."* — is what makes the failing case legible. Note also that Prettier's URL sharing needs **no backend**: `LZString.compressToEncodedURIComponent(JSON.stringify(state))` into `location.hash` via `history.replaceState`. Ruff's playground needs Workers KV for the same feature [20]. If `computed` ever ships a share surface, copy Prettier, not Ruff.

### 3.3 twoslash, and the ceiling it hits

Twoslash runs the real TypeScript compiler over documentation samples at build time and *injects* the results: `^?` pulls the inferred type of an identifier on the line above, `^|` shows completions, `// ---cut---` hides setup that is nonetheless compiled, `// @showEmit` replaces the sample with the emitted `.js` [29][30].

What it cannot do: it type-checks, it does not run — a sample that compiles and returns the wrong value passes. `// @noErrors` is an unbounded, invisible escape hatch. It is TypeScript-only.

**Analysis.** Twoslash is proof that *build-time verification of documentation is a category developers already accept and pay for* — it ships in the TypeScript handbook and in Vue's, Nuxt's and Vite's docs. That is the beachhead argument. The distinction to draw on the page: **twoslash verifies that a code sample is well-typed; `computed` verifies that a statement about the repository is still true.** Twoslash cannot check a file tree, a `--help` synopsis, an ADR index, a rule count or a platform list — which is all of what actually rots in a context file.

### 3.4 The self-referential selling point

**Analysis, and this is the most persuasive paragraph available to the site.** Every demo surveyed in this section goes stale silently, and the good ones know it: mise writes "Illustrative output" [9], Bun writes "Output abridged from Bun v1.4.2" [1]. Those disclaimers are what a careful maintainer writes when they know the block is a mock and cannot afford to make it real. **`computed` replaces the disclaimer with a check.** A landing page whose `CODE`/`OUTPUT` panes are computed regions under `computed check` would be the first before/after on the internet that is provably current — and the page can say so, with the sums visible.

## 4. Documentation as a maintenance cost, and the family `computed` belongs to

### 4.1 The cost claim, sourced rather than asserted

Diátaxis states it as a permanent tax [34]:

> "Finally, all of the characteristics of functional quality appear to us, as documentation creators, as **burdens and constraints**. Each one of them represents a test or challenge we might fail. Or, even if we have met one *now*, **we can never rest, because the next release or update means that we'll have to check our work once again, against the thing that it's documenting**."

And on Reference specifically — the genre `computed` operates in [35]:

> "Reference material is like a map. **A map tells you what you need to know about the territory, without having to go out and check the territory for yourself**."
> "**Sub-commands are: a, b, c, d, e, f.** List commands, options, operations, features, flags, limitations, error messages, etc."
> "Some reference material (such as API documentation) can be **generated automatically by the software it describes, which is a powerful way of ensuring that it remains faithfully accurate to the code**."

Note the scope of that endorsement: *API documentation*. Diátaxis names the class of fact — subcommands, options, flags, limitations, error messages — and endorses generation only for the slice that existing tooling reaches. **The gap between what Diátaxis says reference material *is* and what the execution family can *touch* is the opportunity.**

Write the Docs is blunter, and its ARID principle is the clearest statement anywhere that documentation is duplicated state [36]:

> "**Consider incorrect documentation to be worse than missing documentation.**"
> "Some amount of business logic described by your code must be described again in your documentation… **just by writing any documentation, you are repeating yourself.**"
> "The goal here is to **prevent any parallel maintenance (or worse — lack of maintenance) of the same information across multiple sources**."

Google ranks staleness as one of five named failure modes worth a button on every page it publishes: the per-page feedback widget's thumbs-down categories are "Missing the information I need", "Too complicated / too many steps", **"Out of date"**, "Samples / code issue", "Other" [37].

### 4.3 The gold: projects that explicitly declined

**pulp/pulpcore#5593**, on a proposed plugin feature matrix — maintainer `mdellweg` [175]:

> "As history has shown to me, such a feature matrix is created by hand by one individual, because there is no way to automate it… But the reality is, it will get out of date and the more outdated, the harder it gets to update again. **This is like balancing a broomstick on your nose. Eventually it will fall on the floor.**"

and when a user said they would personally like such a listing: **"That is exactly the reason not to do it."**

**zarr-developers/zarr_implementations#66** records the full decline-then-reach-for-automation arc [176]: *"I agree having exhaustive feature completeness scores would be quite a chore, and very hard to keep up to date"* → *"it would quickly become out of date"* → *"though I agree it would become out of date if done manually - perhaps a github actions workflow could be developed"*.

**mdn/content#45318** declined on the same grounds and extended it to screenshots [177]: *"It's just too much work to maintain and impossible to even know when such references to 'new' things are now outdated"*; a screenshot alternative was rejected because *"They go out of date as soon as the site design changes."*

**Analysis.** These are the most valuable citations in the file for the landing page, because they are maintainers stating, unprompted, that a *valuable* document was *not written* because of maintenance cost. That is the exact shape of the market. The broomstick quote should be on the site.

### 4.4 The "keep the doc true by execution" family, and its ceiling

| Mechanism | Verifies | Cannot verify | Covers "the CLI's subcommand list"? |
|---|---|---|---|
| Rust doctests [58] | Rust blocks compile and run without panic; `no_run` compiles only, `ignore` does nothing | anything that is not a Rust code block; never rewrites the doc | **No** — you can assert over `Cli::command()`, but the prose listing the subcommands is never touched |
| Python `doctest` [63] | captured output equals a hand-written expected literal | prose, tables, lists, headings | tripwire only — the list *is* the hand-typed expected block, never repaired |
| Go Examples [64][65] | stdout equals `// Output:`; no comment means "compiled but not executed" | any document file — docs are generated *from* code | essentially no |
| Sphinx `ext.doctest` [66] | output equals `testoutput::`; `testsetup::` hides machinery | prose, tables, toctrees; the HTML builder never sees results | tripwire only, and only under `-b doctest` |
| Deno `test --doc` [67] | type-checks **and runs** `ts`/`js` fences in real Markdown files; **no expected-output mechanism at all** | values, unless you assert them | reaches real `.md`, but the doc then shows *test code*, not a readable list |
| ExUnit.DocTest [68] | evaluated result equals expected inspected value | anything outside module attributes; reads no Markdown file | no |
| mdBook [61][62] | `mdbook test` runs Rust blocks; `{{#include}}` inlines real file content at build time | command output, directory walks; the source `.md` is never updated | **no** — include cannot run a command |
| nbval [69] | fresh notebook outputs equal stored outputs | anything outside an `.ipynb`; writes nothing | the closest tripwire, but `.ipynb` only |
| Jupyter Book / MyST-NB [70][71] | **nothing** — it inserts outputs, no expectation exists to violate | any claim in the *source* file | prints the live list on the *published* page; the repo's Markdown stays stale |
| **cog** [72] | `--check` re-runs everything and compares; `-c` stores an **output** checksum against hand edits | nothing structurally — but the check is a full re-execution | **yes, and this is how it is actually done** — simonw/llm's `docs/help.md` recurses the live Click tree [55] |
| **trycmd** [74] | `$ cmd` transcripts inside ```` ```console ```` fences **in real `README.md`**, stdout+stderr+exit code, with `[..]` elision | anything not a shell transcript; needs the binary built | **yes, by verification** — but it never writes prose, and a tree needs `$ tree` |

**The sharp version of the claim, which is the defensible one.** The execution family *compares*; in every comparator the doc-facing fact **is** the hand-written expected literal, so repair is manual retyping and detection only happens when the suite runs. The one pure generator (MyST-NB) writes the fact correctly but into the *build output*, leaving the repo's Markdown untouched and unchecked. And every member requires the fact to be *a code block with a prompt or an output marker*: none attaches to a Markdown table of environment variables, a bullet list of ADRs, or a fenced tree.

The two tools that genuinely cover "the list of subcommands" — cog and trycmd — are not doctest mechanisms. Neither covers a directory tree, an ADR index or a module inventory without shelling out. **Nothing keeps a *statement about the repository* true by writing it.**

## 5. The agent side

### 5.1 What the formats say belongs in the file

Anthropic's best-practices page carries a two-column table whose exclude column names exactly what `computed` computes [92]:

| ✅ Include | ❌ Exclude |
|---|---|
| Bash commands Claude can't guess | **Anything Claude can figure out by reading code** |
| Code style rules that differ from defaults | Standard language conventions |
| Testing instructions and preferred test runners | Detailed API documentation |
| Repository etiquette | **Information that changes frequently** |
| Architectural decisions specific to your project | Long explanations |
| Developer environment quirks | **File-by-file descriptions of the codebase** |
| Common gotchas or non-obvious behaviors | Self-evident practices |

and the memory page describes a tool that acts on it [91]: *"The `/doctor` checkup proposes trims for a checked-in CLAUDE.md: it cuts content Claude can derive from the codebase, such as **directory layouts, dependency lists, and architecture overviews**, and keeps pitfalls, rationale, and conventions that differ from tool defaults."*

**But the same docs set contradicts itself**, and the contradiction is the opening. The feature overview says [94]: *"Put it in CLAUDE.md if Claude should always know it: coding conventions, build commands, **project structure**, 'never do X' rules."* The blog says [95] CLAUDE.md should contain *"Build commands, directory layout, monorepo structure, coding conventions, team norms."* One page tells you to put the layout in; another ships a tool to take it out.

**Analysis.** The unstated reason for the removal advice is that a hand-written layout *rots*, not that layout is worthless. `/doctor` cuts the fact because the fact cannot be trusted. That is the entire pitch in one sentence: keep the fact, drop the rot.

The other formats:

- **agents.md** [98] — *"a README for agents"*; recommended sections are Project overview, Build and test commands, Code style, Testing instructions, Security considerations. Its entire maintenance guidance is *"Treat AGENTS.md as living documentation."*
- **Cursor rules** [99] — four activation types (Always Apply / Apply Intelligently / Apply to Specific Files / Apply Manually), `.mdc` with `description`, `globs`, `alwaysApply`. Its documented anti-staleness rule is the most on-point sentence in this whole strand: *"**Reference files instead of copying their contents—this keeps rules short and prevents them from becoming stale as code changes.**"*
- **GitHub Copilot** [100][101] — recommends *"A summary of what the repository does"*, *"the size of the repo, the type of the project, the languages, frameworks, or target runtimes in use"*, *"for each of bootstrap, build, test, run, lint … the sequence of steps … as well as the versions of any runtime or build tools used"*, and *"the relative paths to the main project files, the location of configuration files"*. **Nearly all of that is computable.** And GitHub explicitly lists *"Requests to refer to external resources when formulating a response"* among instructions that *"may not have the intended results"* [100] — the opposite of Cursor's advice.
- **Windsurf/Devin** [102], **Continue.dev** [103], **Codex** [109][110], **Gemini CLI** [112] — all concatenate a Markdown file hierarchy at launch. Codex caps the merged size at `project_doc_max_bytes` (32 KiB default) and **truncates silently to a log**, which produced openai/codex#7138, *"`AGENTS.md` is silently truncated without any warning within the TUI"*, closed as not planned [111]. A context file can be wrong not only by being stale but by being half-loaded.

**Analysis.** Cursor says *don't copy, it goes stale*; GitHub says *external references don't work*; Anthropic says *cut the derivable content* and also *put the project structure in*. Three vendors, three incompatible mitigations, because the third option — inline the fact and keep it verified — does not exist as a tool. That is the paragraph the landing page's "why" section is missing.

### 5.2 Aider computes what everyone else asks a human to write

This is the framing. Aider's repo map is *"a concise map of your whole git repository that includes the most important classes and functions along with their types and call signatures"* [104]. It is built with tree-sitter over per-language `{lang}-tags.scm` queries producing `Tag(rel_fname, fname, line, name, kind)` where `kind` is `"def"` or `"ref"` [105][106]. Ranking is **PageRank over a reference graph** — `nx.MultiDiGraph()` with edges referencer → definer, then `nx.pagerank(G, weight="weight", **pers_args)` — with weight multipliers that encode what an agent actually needs [106]:

```python
if ident in mentioned_idents:                              mul *= 10
if (is_snake or is_kebab or is_camel) and len(ident) >= 8: mul *= 10
if ident.startswith("_"):                                  mul *= 0.1
if len(defines[ident]) > 5:                                mul *= 0.1
if referencer in chat_rel_fnames:                      use_mul *= 50
```

The budget is `--map-tokens` default 1024 [107], hit by **binary search** over the ranked tag list. `--map-refresh` defaults to `auto`, which caches only when `self.map_processing_time > 1.0` — **it recomputes on every turn unless computing is slow** — with per-file tags cached in a `diskcache.Cache` **keyed on filename + mtime** [106]. Aider's *hand-written* file is separate and tiny: `CONVENTIONS.md`, whose documented example content is two lines — *"Prefer httpx over requests for making http requests. Use types everywhere possible."* [108].

**Analysis.** Aider splits agent context cleanly in two: the *structural* half is computed from the AST on every turn under a token budget and invalidated by mtime; the *taste* half is a hand-written file of preferences. Every Markdown context-file format merges both halves into one hand-written file and hopes the structural half stays true. `computed` is the mechanism that lets a merged file keep aider's property — and unlike aider's map, the result is committed, diffable in review, and readable by every tool, not just one client.

### 5.3 Where this sits in the guides-and-sensors taxonomy the site already cites

Böckeler's axes [116]:

> "**Guides (feedforward controls)** - anticipate the agent's behaviour and aim to steer it before it acts."
> "**Sensors (feedback controls)** - observe after the agent acts and help it self-correct."
> "**Computational** - deterministic and fast, run by the CPU. Tests, linters, type checkers, structural analysis. Run in milliseconds to seconds; results are reliable. **Inferential** - Semantic analysis, AI code review, 'LLM as judge'… Slower and more expensive; results are more non-deterministic."

Her examples table places the whole category in one cell: **`Coding conventions | feedforward | Inferential | AGENTS.md, Skills`**. Computational feedforward guides in her table are code mods and LSP integration — *"There is increased chatter among developers about the integration of LSPs and code intelligence in coding agents, examples of computational feedforward guides"* — and **contain no documentation example**.

She never writes "stale" or "rot", but she leaves the door open twice [116]: *"How do we keep a harness coherent as it grows, with guides and sensors in sync, not contradicting each other?"* and *"Feedforward and feedback controls are currently scattered across delivery steps, **there's real potential for tooling that helps configure, sync, and reason about them as a system**."*

**Analysis.** The site already cites this article for the guides/sensors framing. It should cite it for the *empty cell*. A computed region is a **computational feedforward guide made of documentation** — deterministic, CPU-run, millisecond-fast, verifiable — and aider's repo map is the only other occupant. That is a sharper claim than "the context file gets no signal", and it is her own taxonomy making it.

**One repo states the thesis and violates it in the same section.** `cloudflare/workers-sdk/AGENTS.md` opens [126]:

> "Prefer authoritative configuration and documentation over copying details into this file: **copied versions, rule lists, and counts become stale.**"

Three lines later: *"The root `package.json` is authoritative for available scripts"* — followed by a hand-copied list of nine of those scripts and a 13-row location table. **They knew the risk, wrote the warning, and copied anyway, because delegation alone leaves the agent without the fact.** That paragraph is the best single artifact in this research for motivating the tool, and it belongs on the landing page.

`rust-lang/rust` takes the opposite extreme [129]: *"Agent instructions … may only link to, summarize, or conservatively operationalize existing human-facing documentation… Do not make an agent file the sole source of a rule."* Grafana shows delegation's cost [130]: *"Node.js — version pinned in `.nvmrc` (check that file for the exact version)"* — correct forever, but every lookup is a round trip the agent must decide to make.

### 5.6 The failure modes, from real reports

The three predicted failures all appear, in named issues [127]:

- **Dead file paths.** PostHog#91369: an agent reading `rust/personhog-router/AGENTS.md` for test conventions was *"sent to `src/service/tests/mocks.rs`, a path removed when the typed proxy was deleted"* — *"pointed the file's only audience at a directory it could try to recreate."* grafana/k6#6373: *"`AGENTS.md` references two module paths that don't exist in the repository… the two sections contradicted each other."*
- **Removed or renamed commands.** Airflow's validator, above, citing #69861 and #43979 [125].
- **Editing against a changed API.** bbot#3420: AGENTS.md documented module option dicts that BBOT 3.0+ *refuses to load* — *"this is the one doc bug that reliably produces a broken first module."* unoplatform/uno#24326, from an Uno maintainer: `AGENTS.md` *"is loaded into context on **every** agent session in this repo, so anything stale in it is both a token cost and an active source of wrong code"*; it documented `DependencyObject` as an interface when it is a class — *"An agent following either writes broken code."*

And the best single anecdote, wildcard/caro#1444 [127]: a CLAUDE.md version drift that was *"a recurrence of #1044… That fix updated the banner but did not add `CLAUDE.md` to the release-version-alignment checklist, so drift recurred."* **The human remedy for drift was a manual checklist item, and it was forgotten.**

Why a wrong line is worse than a missing one: Anthropic states instructions are *"context, not enforced configuration"* with *"no guarantee of strict compliance"* [91] — the agent will *try* to obey the false statement. shopware/frontends#2678 puts the mechanism plainly: *"every line that duplicates live state rots and then actively misleads (**the model trusts the file over its own inference**)."* stablyai/orca#12544: *"the stale file looks authoritative."* And Chroma's *Context Rot* [120] shows the cost compounds — *"even a single distractor reduces performance relative to the baseline… adding four distractors compounds this degradation further."*

**A whole category of tools now exists solely because these files rot** [128]: `agnix` (*"Catch broken agent configs before your AI tools silently ignore them"*), `driftlint` (*"Your CLAUDE.md is lying to your agent"*, with rules named `dead-path`, `dead-command`, `stale-knowledge`, `twin-drift`), `agents-lint` (*"**AGENTS.md files rot.** You write them once, then the codebase evolves… and the file silently misleads your AI coding agents"*), `ctxlint`, `context-drift`. And separately, the repo-packers that **compute** context but emit a throwaway prompt: repomix, gitingest, code2prompt, files-to-prompt.

**The structural gap.** The packers compute repo facts into an ephemeral prompt. The linters check a hand-written file after the fact and report drift. **Nobody computes the derivable part in place, inside the file the agent already reads, and refuses a hand-edit.** That slot is empty.

### 5.7 Two things to say honestly rather than let a reader find

**(a) The strongest counter-evidence.** ETH Zurich's *Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?* [121] found *"providing context files does not generally improve task success rates, while increasing inference cost by over 20% on average"* and, specifically, *"while instructions in the context files are well followed by coding agents, **repository overviews, although popular and recommended by model providers, are not helpful**."*

**Analysis.** This deserves a direct answer, not omission. Two responses hold. First, the study measures the benefit of a *correct* overview; it does not measure the cost of a *wrong* one, and §5.6 is a list of wrong ones producing broken code. A stale tree is not neutral, it is a distractor [120]. Second, the finding independently corroborates `/doctor`'s trim policy [91] and argues that derivable content should be *cheap and verified* rather than *long and hand-written* — which is exactly `computed`'s bargain, not a refutation of it. Do not overclaim past this paper, and do not pitch `computed` as making agents smarter. Pitch it as making one fifth of the file stop lying.

**(b) The growth measurement.** *Why Does CLAUDE.md Keep Growing? Catastrophic Remembering in Agentic Coding* [122], over 247,694 instruction lifetimes across 1,867 repositories, finds *"agentic prompts grow without bound, more than tripling over their lifetime (+226%), gaining +4.9 net instructions every commit; further, the older an instruction gets, the less likely it is to be deleted (log-hazard -0.032/commit)"*. **Analysis:** that is direct measurement that the "prune it periodically" advice in every vendor doc does not happen at scale. A region that shrinks and regrows with the repo is the only kind of line that does not accumulate.

## 6. The catalogue: regions nobody writes because they rot

**How to read this.** Each entry gives the region, a marker line in `computed`'s real grammar, who benefits, what it costs by hand today, and whether `discover-regions` already covers it. Grammar constraints checked against `src/marker.rs` and verified by running the tool: an unquoted value may not contain whitespace; a quoted value takes `\"` as its only escape and may not contain `-->`; `exec` requires `cmd=` and **exactly one** of `inputs=` or `volatile`; the default sink is `fence` for `tree` and `raw` for `exec`.

**Two rules that shape every entry, both verified in `src/loader.rs`:**

1. **`inputs=` reads the full bytes of every matched file into the snapshot.** `inputs=src/**` on a large repo makes `check` O(repo bytes). Point `inputs=` at the smallest set that determines the output.
2. **`run` skips a fresh region's loader entirely.** So a command whose output is *not* byte-stable across runs — a timing, a size, a coverage percentage — does not churn, because it is only re-run when its declared inputs move. **Analysis:** this makes a whole class of region viable that would be unusable under a re-run-to-check tool, and it is worth stating on the site. It is the cache being a feature, not an optimisation.

**A third rule from the skill, which the catalogue leans on heavily** [`discover-regions`]: *"A command long enough to need quoting belongs in a script under `scripts/`, named in `cmd=` and listed in `inputs=` alongside what it reads, so editing the script makes the region stale too."* Most entries below are written that way; the ones short enough to inline are inlined.

### 6.1 What `discover-regions` already covers

The skill's table names five candidate kinds: a file tree or directory listing (`tree`), a pasted command's output (`exec` with `inputs=`), an index built from files such as ADRs or migrations, a table of contents, and a version/count/date stamp. It also names the correct exclusion — *"Anything a person decided… Computing them takes the decision away from the person making it."*

**Analysis.** That is the right frame and the right exclusion, but it is a taxonomy of *shapes*, not a catalogue of *facts*. Every entry below either names a fact the skill's shapes admit but nobody thinks of, or falls outside the five shapes. ### 6.6 The honest negative results

**Analysis, and these belong in the file so nobody re-derives them.**

- **`cargo build --timings` emits HTML only** [153]. A build-timing region is not a one-liner; it needs scraping. Drop it or caveat it.
- **Git-history-derived regions have no honest `inputs=`.** The truth depends on `.git/refs` and commit objects, which `inputs=` cannot snapshot cheaply — `files_under` recurses the whole prefix directory before filtering, so `inputs=.git/HEAD` walks all of `.git` (read in `src/loader.rs`). Every entry of this kind must be `volatile`, and `volatile` means `check` always passes. This is a real gap and arguably the strongest argument for a future `git` loader.
- **`cargo public-api`'s output ordering is not documented as stable** [131], and it needs a nightly toolchain present. `cargo license`'s `-j`/`-t` columns are undocumented [137]. `taplo` generates no docs at all [E1] — do not list it.
- **`volatile` regions are a convenience, not a guarantee.** Any entry above marked `volatile` re-renders on every `run` and is never checked. Say so wherever one is recommended.
- **Prusti is unmaintained** — HEAD dated 2024-03-26 [E1]. Only `cargo kani list` produces an invariant table today [174].

### 6.7 The one line the catalogue is for

**Analysis.** Forty regions is not a feature list; it is the answer to the owner's question. The reason none of these exist in real repos is not that nobody wants them — §4.3 has maintainers saying, in their own words, that they want them and refuse to write them. It is that the cost of a hand-maintained inventory is unbounded and the cost of a wrong one is worse than nothing. `computed` changes the arithmetic: the marginal cost of the thirty-first region is one line and a script, and the marginal cost of *keeping* it is zero, because `check` runs in under 10 ms and executes nothing. **The pitch is not "keep your file tree fresh". It is "here are thirty things you decided not to document, and the reason you decided that no longer holds."**

## 7. Site architecture: what the whole site needs

**Analysis throughout this section**, grounded in the mechanics of §2 and the gaps measured in §1.

**The page count is right; the page order is not.** Today: a landing page that argues the mechanism, and a rules page. What converts a reader into a user is a third thing — a page of *what to compute*, which is §6 turned into a browsable list. Every page in §2 that converts has this: Bun's "Four tools", oxc's per-subproduct sections, Biome's three artifact sections. `computed`'s equivalent is not four tools, it is forty regions.

Proposed shape, in the order a reader needs it:

1. **Landing page.** Fold: headline, one-line install, and the artifact — a real before/after of a `CLAUDE.md` region, not a tree. Second screenful: the measured decay number and the cost of checking. Third: three region examples that are not file trees (a `--help` synopsis, an error table, a module map). Then the comparison table, then install.
2. **A catalogue page — the missing one.** Thirty regions, filterable by loader and by beneficiary, each with a copy-pasteable marker line and one line on what makes it stale. This is the page a reader sends to a colleague, and the page an agent reads. It is also the page most cheaply kept honest, because every marker on it can be rendered from a real repo.
3. **How it works.** Unchanged; it is good.
4. **A "for agents" surface.** Turborepo serves an agent-oriented index to non-browser user agents pointing at `/llms-full.txt`, and states that any URL takes a `.md` suffix [11]. `computed`'s audience is agent-adjacent by definition, and its docs are already Markdown. Publishing `REFERENCE.md` at a stable URL and linking it from every page costs nothing.

**Fold-level changes, each borrowed from a named page:**

- Pair install with the command that makes the artifact, in one block, the way Biome does [2] — `cargo install computed` and `computed run` should be adjacent, not in separate sections.
- Put the version in the install line, the way Bun puts it in the button [1].
- Add a `reproduce →` link next to every number, the way Bun does [1]. The decay statistic in §1 should link to the `git log` invocation that produces it.
- Show a real refusal. The stderr line `CLAUDE.md:40 deps exec edited refused; run with --force` is the most distinctive thing the tool prints and it appears nowhere on the site.
- Name a duration on any demo, the way difftastic's "60 Second Demo" does [32].
- State the passing case out loud, the way Prettier's playground does with *"✓ Second format is unchanged."* [18] — `computed run` writing nothing on the second pass is the whole guarantee and it is currently a bullet in a list.

**What not to build.** A playground. Ruff needs Workers KV for share links [20]; Prettier needs a WASM build and a worker [18]. `computed`'s artifact is a text file, and a rendered before/after region on a static page delivers the same conviction for none of the cost — with the added property, unique to this tool, that the page's own copy can be verified in CI.

## 8. Self-referential proof

### 8.1 How other tools make dogfooding legible, and how badly

| Tool | The device | Visible to a casual reader? |
|---|---|---|
| **markdown-magic** [198] | A sentence in the rendered README: *"This `README.md` is generated with `markdown-magic` [view the raw file](…) to see how."* | **Yes** — the only unambiguous example found |
| cog [193][194][196][197] | A cogged region in `docs/running.rst` closed by `.. {{{end}}} (sum: PC7aU7vkZv)`; a `make lintdoc` target with `--check-fail-msg='Docs need to be updated: \`make cogdoc\`'`; a CI step **named** "Check the docs are up-to-date" | **No** — the rendered docs page shows a plain `cog -h` block with no provenance at all |
| all-contributors [201] | Markers whose opener carries its own instruction — `<!-- ALL-CONTRIBUTORS-LIST:START - Do not remove or modify this section -->` — plus a live badge counting the region's source of truth | Partly — the badge yes, the markers only in raw |
| git-cliff [199][200] | `<!-- generated by git-cliff -->` as the last line of its own CHANGELOG | **No** — an HTML comment, invisible when rendered, and it links to nothing |
| terraform-docs [202] | Documents `BEGIN_TF_DOCS`/`END_TF_DOCS` in its README but **does not use them on itself** | n/a — a counter-example |
| Starlight [203] | Two versioned generator metas: `<meta name="generator" content="Astro v7.2.10"/>` and `content="Starlight v0.42.0"` | No — raw source only |
| mdBook [206] | `<!-- Book generated using mdBook -->`, **unversioned** | No, and it proves nothing checkable |

**Two details worth stealing from cog.** It runs on its own docs with **non-default markers** (`{{{cog }}} {{{end}}}` via `--markers`) *so the prose can discuss the default markers without the tool eating them* — the comment in the region says so. And all-contributors nests its region **inside two other tools' ignore fences** (`prettier-ignore-start`/`end`, `markdownlint-disable`/`restore`) [201], because a generated region and a formatter otherwise fight forever. **Analysis:** both are live interop problems for `computed`. The first is already solved — markers inside a fenced code block are prose, which is how this file and the site's examples survive. The second is not: a repo running prettier or markdownlint over `CLAUDE.md` will reformat a region body and turn it `edited`. That belongs in `discover-regions` and, arguably, in the spec's open questions, which currently mentions *"whether sinks emit prettier range-ignore comments"* — this survey says yes, and names the exact fences.

### 8.2 The provenance conventions, and why none of them fit

The HTML Standard on `generator` [213]:

> "The value must be a free-form string that identifies one of the software packages used to generate the document. **This value must not be used on pages whose markup is not generated by software**, e.g. pages whose markup was written by a user in a text editor."

Go's convention [216]:

> "generated source should have a line that matches the following regular expression (in Go syntax): `^// Code generated .* DO NOT EDIT\.$` This line must appear before the first non-comment, non-blank text in the file."

GitHub Linguist's `.gitattributes` attribute `linguist-generated` means **"Excluded from stats, hidden in diffs"** [217].

**Analysis: every one of these is file-granular, and that is the gap.** `generator`, `DO NOT EDIT.` and `linguist-generated` all say *this whole file is machine output*. A file with three computed regions and two hundred lines of prose fits none of them, and marking `CLAUDE.md` as `linguist-generated` would hide *hand-written* changes from diffs — actively wrong. The nearest honest device is the one all-contributors uses and `computed` already has: **put the warning in the marker itself.** The opener suffix `| do not edit; run computed` is region-granular, needs no external registry, and travels with the region. The site should say that this is a deliberate choice, because "why not a `DO NOT EDIT` banner" is the obvious question and ADR 0003 already answers it (*"There is no file-level banner; the opener suffix is the generated signal, true at the granularity it claims"*).

### 8.3 Can the site's own HTML carry regions? Yes, today, with one caveat

**Verified by running the tool** in a scratch repository, `65650a8`:

```
<!-- computed exec cmd="printf '<li><code>run</code></li>\n'" inputs=page.html.dep as=raw name=cmds | do not edit; run computed -->

<li><code>run</code></li>

<!-- /computed in=12634a7a…c2e9 out=7673c552…ff7bc -->
```

`computed run page.html` wrote it; `computed check page.html` exited 0. A `tree` region with `as=raw` inside a `<pre>` also rendered correctly, and a `cmd=` containing `--depth 1` and `2>/dev/null` parsed without complaint.

**What works today, unchanged:** the markers are already whole-line HTML comments, which are valid in both file types; `computed` reads an explicit path whatever its extension; `as=raw` produces correct HTML.

**What does not port: the `fence` sink.** In an `.html` file, ```` ``` ```` is three literal backticks in a text node — no code block, no escaping — and any `<`, `&` or `</div>` in the loader output is interpreted as markup. **Analysis: a `fence` sink pointed at HTML produces a syntactically valid file with semantically wrong content, silently, which is worse than refusing.** The correct HTML analogue is a `<pre><code>` sink with `&`, `<`, `>` escaped. That is a small, well-scoped addition and it is the one thing standing between the site and being self-verifying.

**On the comment-syntax worry, and a correction.** The modern restriction is **not** "a comment must not contain `--`". HTML Standard §13.1.6 [226]:

> "the text must not start with the string `">"`, nor start with the string `"->"`, nor contain the strings `"<!--"`, `"-->"`, or `"--!>"`, nor end with the string `"<!-"`."

So `<!-- computed exec cmd="cargo tree --depth 1" -->` is a conforming HTML comment; only `-->` is a genuine parsing hazard, and `src/marker.rs` already rejects it in an attribute value. **XML is stricter** [227] — *"the string `"--"` (double-hyphen) MUST NOT occur within comments"* — so if `computed` ever targets `.xhtml` or `.svg`, `--` in `cmd=` becomes a hard error. Worth a line in the spec's open questions, not a change now.

**And on Markdown, the reason the current design is safe:** CommonMark HTML block type 2 starts at a line beginning `<!--` and ends at a line containing `-->` [228]. `computed`'s markers open and close on the same line, so each is a self-contained one-line HTML block and the fenced body between them parses as normal Markdown. A marker that opened on one line and closed on another would swallow everything up to the `-->`. Types 6 and 7 end at a **blank line**, which is why the `raw` sink's blank-line padding is the right shape. This is worth documenting on the how-it-works page, because it is the sort of detail that makes a careful reader trust the rest.

### 8.4 What the site should actually do

**Analysis, concrete and ordered by cost.**

1. **Put the decay number on the fold, with its command.** *"In this repository, the tree region's body changed in 8 of the last 41 commits."* with a `reproduce →` link, the way Bun does [1]. It is measured, it is reproducible from a clone, and it converts the abstract claim into an observation.
2. **Show the sums from the real file, not an invented one.** The hero card currently shows `in=ab558c86…` and `out=d53ea485…`, which are fabricated. The real ones are in `CLAUDE.md` at `65650a8`. A reader who checks and finds they match learns more about the project than any copy could tell them.
3. **Add a "this block is computed" affordance that is visible when rendered.** markdown-magic's one sentence [198] is the whole state of the art. `computed`'s version should be better: a small caption under any computed block on the site reading what command produced it and when `check` last passed.
4. **Put `docs/index.html` and `docs/how-it-works.html` under `computed check` in CI.** They carry four of the twelve hand-copied table copies measured in §1 and are currently unchecked, because CI runs `computed check` with no paths and discovery walks `.md` only. Naming them explicitly is a one-line change to `ci.yml` and needs the `<pre><code>` sink from §8.3 for the fenced tables.
5. **A `dynamic/json` badge is the cheapest live-state device.** `https://img.shields.io/badge/dynamic/json?url=<URL>&query=<JSONPath>&label=<label>` [210] — verified live — reads a JSON file in the repo with no service to run. A tiny sidecar written by CI (region count, last commit at which `check` passed) becomes a self-proving badge. Note the granularity limit on the alternative: a GitHub Actions badge is per **workflow**, not per step [211], so a "regions verified" badge needs its own workflow file.
6. **Copy vhs-action's PR-comment pattern** [25]. On a PR whose diff touches a region's declared inputs, post — and on re-push, *upsert* by searching for a marker comment — the diff `run --dry-run` would write. That is a natural GitHub Action, a strong second product surface, and it makes the tool visible at exactly the moment a reviewer cares.
