The markers

A region is the span between two whole-line HTML comments. The first names what fills the region. The second carries the hashes. Anything between them is the body, and the tool owns it.

<!-- computed tree src=. depth=2 name=layout | do not edit; run computed -->
```text
.
├── docs
└── src
```
<!-- /computed in=9f3a1c0b… out=41c0d9e8… -->
In the opening commentMeaning
tree · exec · file · …The first word picks what fills the region. There are ten, below.
name=Optional. Reports use it instead of the line number. Unique per file.
as=fence · as=raw · as=tableHow the text lands in the file. fence wraps it in a code block, raw pastes it as Markdown, table turns CSV or JSON Lines into a Markdown table. Tree defaults to fence, exec to raw.
lang=The language on the code fence. Empty by default.
max-lines=NKeep the first N lines of the output and a note of how many were cut.
on-stale=warncheck reports the region when it is stale, and does not fail on it.
| do not edit; run computedThe tool adds this suffix when it renders. You do not write it, and the parser ignores it.

A closing comment with no hashes means the region has never been rendered. A closing comment with one hash, an unknown word, a duplicate name, or a region inside another region is a parse error. The file is left alone and the exit code is 2. Markers inside a fenced code block are ignored, which is how this page's examples survive.

A marker is one line. Wrapping a long opener across two lines is an error — unterminated marker: the line does not end with -->, exit 2 — and that is deliberate rather than laziness. In CommonMark a line beginning <!-- opens an HTML block that runs until a line containing -->, so a marker that opened on one line and closed on another would swallow every line in between and hand it to the HTML parser. Keeping both markers to a single line makes each one a self-contained block, and leaves the body between them to parse as ordinary Markdown.

The old advice that an HTML comment may not contain -- no longer holds: the HTML Standard forbids the text starting with > or ->, containing <!--, --> or --!>, or ending with <!-. So cmd="cargo tree --depth 1" is a conforming comment, and only --> is a real hazard — which the parser rejects inside a quoted value. XML is the stricter one, where any -- is illegal; that matters only if a region is ever asked to live in an .svg or an .xhtml file.

The two hashes

in= is a SHA-256 over the opening comment and a snapshot of the inputs. For tree, the snapshot is the list of paths it printed. For exec, it is the bytes of every file named in inputs=. For a region that reads part of a file, such as one section or one key, it is only that part. If any of it changes, the region is stale.

out= is a SHA-256 over the body, byte for byte. If it no longer matches, someone edited the body.

Both live in the closing comment, so a fresh clone carries everything check needs. There is no cache and no sidecar file. The binary's version is not part of either hash, so upgrading does not make every region stale.

The loaders

tree

<!-- computed tree src=. depth=2 all dirs -->

Lists a directory the way tree does, without sizes or dates. src= defaults to the file's own directory and depth= to unlimited. all includes dotfiles, dirs lists only directories.

Inside a git repository it skips what .gitignore skips, with no flag to turn that on or off. Names are sorted by byte order so two machines print the same listing.

exec

<!-- computed exec cmd="cargo tree --depth 1" inputs=Cargo.lock -->
<!-- computed exec cmd=date volatile -->

Runs cmd= with /bin/sh -c and pastes its standard output. You must say what the command reads. inputs= takes comma-separated globs, and every matched file's bytes go into the snapshot. volatile says the command has no inputs and should run every time.

The command runs with the file's directory as its working directory, a 30 second limit you can change with timeout=, and LC_ALL=C and TZ=UTC set so its output does not depend on the machine. An exec region only runs in a repository you have trusted. See who may run a command.

file src=docs/shared.md pastes one file as it stands, so a section shared by CLAUDE.md and AGENTS.md is written once. section=Install, lines=10-40 or anchor=example takes one part of it, and only that part goes into the snapshot. With as=fence lang=markdown it shows a file as code, markers and all.

Six more read without running anything. value src=Cargo.toml key=package.version takes one field of a TOML, JSON or YAML file. index src="docs/adr/*.md" lists files as links titled by their first heading. toc lists the file's own headings. symbol src=src/lib.rs item=parse part=signature takes one item of a Rust, Python or Go file. git log, git tags and git contributors read the history. remote url=… sha256=… renders a document pinned by its hash. None of them needs trust. transcript runs a shell session and shows each step with its output, and needs trust as exec does.

A computed.toml can name an opener once, as a recipe, and a region writes use recipe=NAME for it.

Relative paths resolve against the directory of the file holding the marker, not the repository root or the shell's working directory. So a region reads the same from a hook, from CI, and from a terminal, and moving the file moves its regions with it. A path that leaves the repository is an error, because such a region would render differently on every machine.

Before the text lands in the file, line endings become LF and trailing newlines are stripped. A command that prints invalid UTF-8, a control character, or a line that looks like a marker outside a fence has failed. A region indented inside a list item gets its body indented to match. When a command fails, times out, or exits non-zero, the old body and both hashes stay, its stderr is printed under the region's line, and the run exits 1. Deleting an input does not blank a region.

The states

Four questions, asked in this order. The first one that says no names the state. check asks them and reports. run asks them and then renders every region that is not fresh.

StateWhat it meanscheckrun
freshBoth hashes match.silent, exit 0left untouched
staleThe inputs or the opening comment changed.reported, exit 1rendered
editedThe body no longer matches out=.reported, exit 1refused, exit 1
stale+editedBoth.reported, exit 1refused, exit 1
volatileAn exec region with no inputs and an unedited body.silentrendered every time
unrenderedThe closing comment has no hashes.reported, exit 1rendered, whatever the body holds
untrustedNot a state of the region but of the clone: an exec region in a repository you have not trusted.not a concern, check runs nothingskipped, exit 1

Because check never runs a command, a command whose output changes for the same inputs is invisible until you pass --force. That is the price of a check that needs no runtime and no trust. computed doctor runs every loader twice and names such a region, and computed trace names the files a command reads that its inputs= leaves out.

Hand edits

The file you commit is the file the tool edits. Outside a marker pair everything is yours and a run never touches it. Inside, the body is the tool's, and an edit there is refused rather than overwritten. The region stays as edited, the whole file is left unwritten, and the run exits 1.

To regenerate, pass --force, which overwrites every edited region in the files you name, or delete both hashes from the closing comment. Editing the opening comment is not a hand edit. It changes in=, so the region is stale and renders on the next run.

The reason to refuse rather than warn is the pre-commit path. A warning from a hook that still writes and exits 0 is an overwrite with a line nobody reads. On CLAUDE.md the editor is usually an agent, and a failed hook is the one signal that reaches it. In Claude Code the plugin gets the signal there sooner: a hook refuses the edit before it lands.

Who may run a command

An exec region runs only in a repository you have trusted on this machine. The model is the one direnv and git's safe.directory use.

computed trust            # this repository, on this machine
computed untrust          # take it back
computed run --trust      # this one invocation, for CI

The grant is stored in ~/.config/computed/trust.toml, keyed by the repository root. Nothing inside a checkout can grant itself. In an untrusted clone, run skips every exec and transcript region, reports it as untrusted, still renders every other region, and exits 1. check never runs a command, so it needs no trust at all.

Only a region that runs a command from the repository needs a grant. The git loader runs git to read history, and that runs nothing the repository controls. A remote region fetches only under a url prefix this machine has allowed with computed allow, and a grant allows no url.

This defends against one thing: cloning a repository and having computed run execute its commands before anyone has read them. A malicious branch pulled into a clone you already trust runs on the next run, the same as a Makefile or a pre-commit hook would.

Commands and exit codes

run [paths]Render every region that is not fresh and write the files. Exit 1 when it wrote, refused, or a command failed.
run --dry-runPrint the diff each file would get, write nothing. The only place the pending diff is shown.
run --forceAlso overwrite edited regions, and re-render fresh ones.
run --trustTreat every file as trusted for this invocation.
check [paths]Report the state of every region. Runs no command. Exit 1 on anything but fresh.
clean [paths]Empty every body and strip the hashes, leaving the markers. The next run rebuilds them.
trust · untrust [path]Grant or revoke exec for the repository containing the path.
update · allow · disallowPin each remote region's document by its SHA-256; keep the url prefixes this machine may fetch.
doctor · traceRender every region twice to find output that is not stable; trace each command to find what inputs= misses.
affected · graph · whyWhich regions a path feeds, what every region reads, and why one is stale, from git history.
stats · dupes · adoptHow much of each file is computed; blocks copied between files; a hand edit written back into its source.
merge · guard · watch · lspA git merge driver, the Claude Code edit guard, a watcher, and a language server.
--only NAMEOnly the regions with that name. Repeat for more.
-vAlso print the regions that are fine.
--format jsonOne JSON document on stdout instead of the report.

With no paths, a command walks the current directory for .md and .markdown files, .claude/ and .github/ included, skipping what .gitignore skips. A file you name is read whatever its extension.

one line per region, on stderr

CLAUDE.md:12 layout tree stale      written
CLAUDE.md:40 deps   exec edited     refused; run with --force
CLAUDE.md:58        exec untrusted  skipped; run `computed trust`
  • exit 0Nothing to report. Everything is fresh.
  • exit 1The content said no. Drift, a written file, a refused edit, a failed command, an untrusted region.
  • exit 2The tool could not answer. A usage error, a parse error, a path outside the repository, an inputs= glob that matches nothing. A region the tool cannot answer is skipped on its own; the rest of its file is still kept current.

How files are written

Every write goes to a temporary file that is then renamed over the original, keeping its permissions. A symlink is written through, so AGENTS.md linked to CLAUDE.md stays a link. A file edited while its commands ran is not overwritten. When one file's inputs= read another, run renders again until both settle, so one run leaves check passing. Nothing is written when the bytes would be identical, so running twice changes nothing and the file's modification time does not move. A file with one refused region is not written at all, even if other regions in it are merely stale. Other files in the same invocation still are.

computed watch runs run again whenever a template or a file its regions read changes. It knows its own writes by their bytes, so a pass it made does not start another.

Files that are not Markdown

Discovery walks .md and .markdown files, but a path you name is read whatever its extension. So a region works today in an HTML page, a YAML issue template, a Rust source file, or anything else where a whole-line HTML comment is legal and harmless. What changes is which sink you can use.

What ports

The markers, unchanged — they are already whole-line HTML comments. The two hashes, unchanged. And as=raw, which pastes the loader's text as it stands.

computed run docs/index.html
computed check CLAUDE.md docs/index.html

What does not

The fence sink. In an HTML file three backticks are three backticks, and a < or & in the loader's output is read as markup. The result is a valid file with wrong content, which is worse than a refusal. Use as=raw and let the generator emit the markup, until an escaping sink exists.

A formatter will fight a region. Prettier or markdownlint running over CLAUDE.md will reformat a body and turn it edited, and the two tools will then undo each other forever. Until computed emits the range-ignore comments itself, wrap the region the way all-contributors does — inside prettier-ignore-start and markdownlint-disable fences.

There is no file-level DO NOT EDIT banner and no linguist-generated attribute, because both are the wrong granularity. A file with three regions and two hundred lines of prose is not machine output, and marking it as such would hide hand-written changes from diffs. The warning belongs in the marker, which is where the opener's | do not edit; run computed suffix puts it. ADR 0003.
