The part of a CLAUDE.md that goes stale is the generated part, the tree or the module list, not the prose. Other tools that rewrite those spans have to rerun the generator to find out, so nobody checks. computed check reads the file, compares the sums, and exits 1. That is cheap enough to run in CI on every push.

Guides and sensors

Birgitta Böckeler splits the controls around a coding agent into two kinds. Guides are feedforward. They steer the agent before it acts. Sensors are feedback. They look at what the agent did and give it a signal to correct against. A CLAUDE.md or AGENTS.md is a guide. The harness injects it ahead of every task, and the agent takes it as an accurate description of the repo.

A guide is only useful while it matches the code. Nothing in the loop notices when the tree or the module table drifts, so the agent starts each task with a picture that was accurate a month ago. A wrong guide does more damage than none, because the agent does not second-guess it.

The two sums add the missing sensor. computed check compares them and exits 1 when a region no longer matches its inputs. It never runs a generator, so it fits in a pre-commit hook and in CI. The context file stays a guide. Its freshness becomes something the harness can measure.

The vocabulary is from Harness engineering for coding agent users, Birgitta Böckeler on martinfowler.com, April 2026.

Two sums, no state

Tools that rewrite a marked span already exist. cog, mdsh, markdown-magic. They store a checksum of what they wrote, at best. None of them store what they read, so "is this fresh" means running every generator again.

Every closer here carries both. The input sum hashes the opener line plus a snapshot of the inputs. The output sum hashes the body. Together they answer both questions from the rendered file alone, with no cache directory that a fresh clone would lose.

Six things a region can be

After a render, each region has one status. The tool reaches it from the prior file and the fresh load, in this order, and nothing else goes into it.

Hand edits are refused, not reverted

An agent that edited a region had a reason. Overwriting it on the next run loses that work without a trace. The region stays, the run exits 1, and regenerating takes an explicit --force or deleting the sum.

A failed loader keeps the last good body

Deleting data.csv does not blank the table. Body and sums stay as they were, the run exits 1 so CI notices, and restoring the file repairs it on the next run.

Loaders read, sinks shape

A loader returns text plus the snapshot the input sum is taken over. A sink turns that text into what lands in the file. Every loader has a default sink; any opener can name another with sink=.

Relative paths resolve against the directory of the file holding the marker, not the repository root or the shell's working directory. So a region reads the same from a pre-commit hook, from CI, or from a terminal, and moving the file moves its regions with it.

One file, two owners

There is no template rendered to a sibling. The file you commit is the file the tool edits, and the tool owns the region bodies and nothing else. Everything outside a marker pair is yours, and a run never touches it.

Inside a region it is the other way round. The output sum hashes the body as written, so run can tell a hand edit from the file alone and refuses to overwrite it. The opener suffix | do not edit; run computed is the only generated-content marker, and it applies to the region, not the file.

The watcher ignores itself

Every write goes through a temp file and rename(2), and nothing is written when the bytes would be identical. So run twice is a no-op and the mtime never moves.

That matters for watch. Its own write comes back as a change event. The loop remembers the last text it wrote and drops any event on the rendered file whose content matches. A non-matching change to that file is someone else's edit, so it runs check rather than overwrite.

The watcher is a convenience. run in a pre-commit hook and check in CI do the real work, so this is a static binary rather than a daemon.

Try it

cargo run -- demo     # scratch repo under .scratch/
cargo run -- run      # render, atomic publish
cargo run -- check    # exit 1 on drift, never writes
cargo run -- watch    # poll → settle → guard → render

# act like someone else in the repo
cargo run -- add-file
cargo run -- edit-region layout
cargo run -- rm-csv
cargo run -- add-sh && cargo run -- trust

Each free-play command prints the next command to run, so you can follow the README scenarios without reading ahead.

Where the code is behind the decisions

Four ADRs are accepted. The prototype has not caught up with all of them.

  • 0002The ADR names the input sum in=. The code writes sum=.
  • 0003In-place is the only layout. The code still renders .tmpl to a sibling.
  • 0004inputs= on exec regions and COMPUTED_ROOT do not exist yet.
  • treeSkips .git and *.tmp, nothing else. The real loader honours .gitignore through the ignore crate.
  • hash32-bit FNV-1a. Fine for a prototype, not for a format files will carry.
